# Crestron AI Skills Registry

Browse and install skills published in the Crestron/CrestronAISkills GitHub repository. This skill replaces the old Copilot CLI `joinSession()` extension of the same name — instead of shell tool handlers, it uses `curl` via Bash plus Claude Code's own skill-installation mechanisms.

## Config

- Registry URL: `https://crestron.github.io/CrestronAISkills/registry.json` (the GitHub Pages build — `registry.json` is generated by CI from `skills/*/skill.md` on every push to `main` and is **not** committed to the repo, so it does not exist at `raw.githubusercontent.com/.../main/registry.json`)
- Skills base URL: `https://raw.githubusercontent.com/Crestron/CrestronAISkills/main/skills`

Note: the org is **Crestron**, not `CrestronEng` — an earlier placeholder value leaked into this codebase in a few places; don't reuse it.

## Search skills

1. Fetch the registry: `curl -fsSL <registry-url>`. Its `skills` array holds objects with `name`, `version`, `author`, `description`, `tags`, `license`, `path`, `homepage`.
2. If the user gave a tag, keep only skills whose `tags` array contains it (case-insensitive exact match).
3. If the user gave a query, score each remaining skill: name match +10, description match +5, tag match +8, author match +3 (per matched term, case-insensitive substring). Drop zero-score skills, sort descending by score.
4. Cap results to the requested limit (default 10, no query/tag = list all up to the limit).
5. Present as a numbered list: `**name** vVERSION by AUTHOR` then description, then `Tags: ...`. If nothing matches, say so and suggest broadening the query.

## Get skill info

1. Fetch the registry and find the skill whose `name` matches case-insensitively.
2. If not found, say so and suggest running a search instead.
3. Otherwise show: name, version, author, license (default "MIT" if absent), description, tags, homepage (if present).
4. Note whether the skill is already installed (see "List installed skills" below) and, if not, mention it can be installed.

## Install a skill

1. Look up the skill by exact name in the registry to confirm it exists and get its canonical `name` and `version`.
2. Fetch its file: `curl -fsSL <skills-base-url>/<name>/skill.md`.
3. Strip the YAML frontmatter before using the body. These files have a `---`-delimited frontmatter block followed by a *second*, empty `---` separator line before the actual instructions start — skip everything through the second `---` line (mirrors the repo's own `awk '/^---$/{n++; next} n>=2{print}'` logic in `Readme.md`), not just the first.
4. Register it as a real, usable skill rather than dropping a bare file:
   - If the `mcp__cowork__save_skill` tool is available (load it via ToolSearch with query `select:mcp__cowork__save_skill` if deferred), call it with the stripped body content. Pass `overwrite: true` only when the user is explicitly reinstalling or updating an already-installed skill.
   - Otherwise (plain Claude Code CLI, not Cowork), follow this repo's own documented convention: write the stripped body to `.claude/commands/<name>.md` inside the user's current project (create the directory first). Claude Code will expose it as `/<name>`.
5. Confirm installation to the user, including the skill's name and version, and where it now lives.

## List installed skills

- In Cowork, load and call `mcp__skills__list_skills` (via ToolSearch with query `select:mcp__skills__list_skills` if deferred) rather than reading a directory.
- In plain Claude Code CLI, list `.claude/commands/*.md` in the current project (this repo's documented install location).
- Report each skill's name (and version if you can determine it). If none are installed, say so and suggest searching the registry.
